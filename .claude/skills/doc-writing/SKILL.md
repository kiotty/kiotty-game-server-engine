# 문서 작성 규칙 (PlatformGLOverlay)

이 저장소의 문서(`docs/**/*.md` 등)를 쓰거나 고칠 때 아래 두 규칙을 지킨다.

## 1. 결정 이력 맥락 블록은 절제한다

문서를 쓰다 보면 "왜 이렇게 바뀌었는가"를 설명하는 맥락 블록을 넣게 된다. 예:

```
> **원 → 타원 일반화**: 초기 요구는 "원"이었으나 응용에서 회전 가능한 타원이
> 필요해져, 원을 **타원의 특수 케이스**로 흡수한다. ... (§7.2)

> **PlatformGLOverlayContext**는 이전 문서의 `PlatformGLOverlayRenderThread`를
> 대체하는 플랫폼 대면 이름이다. ... 둘은 같은 객체를 가리킨다. (§4.2)
```

**사용자가 문서에서 항상 관심 있는 것은 최종 결정이다.** 이런 이력 맥락이 많아지면
지금 무엇을 해야 하는지 헷갈린다. 따라서:

- **기본은 최종 결정만 서술한다.** "이전에는 X였는데 Y로 바꿨다" 류의 개정 이력은
  사용자가 명시적으로 요구하지 않는 한 남기지 않는다.
- 이미 확정된 결정을 그대로 서술한다. 원은 "타원의 특수 케이스로 흡수한다"까지만
  쓰고, 옛 이름(`PlatformGLOverlayRenderThread`)이나 개정 경위는 생략한다.
- 예외: 사용자가 "이 결정의 배경/이력을 남겨줘"라고 명시하면 그때만 맥락 블록을 넣는다.
- 판단이 애매하면 이력 블록을 넣기 전에 사용자에게 남길지 물어본다.

**정리 요청은 이미 상시로 받아 두었다 (2026-08-05).** 문서를 편집할 때 눈에 띄는 이력·경위
블록은 손대는 김에 걷어낸다. 매번 물을 필요 없다. 이유는 위와 같다 — 이력이 쌓인 문서는
지금 무엇을 해야 하는지 읽어낼 수 없게 되고, 그 상태가 되면 아무도 문서를 안 본다.

다만 **문서에서 지우는 것과 코드 주석에서 지우는 것은 다르다.** 코드 주석의 "왜 이렇게
했는가"는 이력이 아니라 현재 코드의 근거이므로 남긴다.

## 2. 각 챕터에 핵심 주제 요약을 단다

가독성을 위해, 각 챕터(주로 `##` 단위 절)의 도입부에 **그 챕터가 전달하려는 핵심
주제를 한두 문장으로** 정리해 준다.

- 챕터 제목 바로 다음, 하위 절(`###`)이 시작되기 전에 한두 문장 요약을 놓는다.
- 한두 문장으로 설명이 부족하면, 요약 문장 다음에 부연 설명 문단을 이어 붙인다.
  (요약을 억지로 한 문장에 욱여넣지 말고, 짧은 요약 + 부연 구조로 간다.)
- 요약은 "무엇을·왜"를 담되 세부 구현은 하위 절에 맡긴다. 요약만 읽어도 그 챕터의
  목적이 잡히게 쓴다.

예시 형태:

```

코어의 정적 구조를 정의한다 — Context가 렌더 스레드를 소유하고, Renderer가 레이어
목록을 들고, OverlayScene이 응용 계층의 유일한 확장점이 된다.

### 4.1 관계
...
```
