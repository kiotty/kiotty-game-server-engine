# 세션 역할 지정

`.claude/agents/*.md` 는 원래 서브에이전트 정의지만, **같은 파일을 메인 세션의
페르소나로도 쓴다.** 역할 정의를 한 곳에만 두기 위해서다.

## 1. 인자 처리

인자로 역할 이름(파일명에서 `.md`를 뗀 것, 예: `cpp-developer`)을 받는다.

**인자가 없으면** — 아래 순서로 역할 목록을 모아 사용자에게 제시하고, 어느 역할을
맡을지 물어본다. 임의로 고르지 않는다.

1. `.claude/agents/*.md` (저장소 역할 — 우선)
2. `~/.claude/agents/*.md` (전역 역할)

각 파일의 frontmatter `name` 과 `description` 첫 문장만 뽑아 한 줄씩 보여준다.
파일 본문 전체를 읽지 않는다.

**인자가 있으면** — 위 1 → 2 순서로 찾는다. 이름이 정확히 맞지 않으면 부분 일치로
후보를 좁히고, 후보가 둘 이상이거나 하나도 없으면 목록을 보여주고 물어본다.
**추측해서 다른 역할을 채택하지 않는다.**

## 2. 역할 채택

찾은 파일을 Read 로 **전체** 읽고, frontmatter 아래 본문을 **이 세션의 행동 지침으로
채택한다.** 서브에이전트를 띄우는 것이 아니다 — 메인 세션이 직접 그 역할이 된다.

- frontmatter 의 `tools` 는 **무시한다.** 서브에이전트 권한 필드일 뿐이고 메인
  세션에는 적용되지 않는다. `name` / `description` 도 지침이 아니라 메타데이터다.
- 본문에 다른 스킬·문서를 우선하라는 문장이 있으면 그것을 존중한다. 이 저장소의
  빌드·명명·문서 규약 스킬은 역할 문서보다 우선한다.
- 역할 문서와 사용자의 직접 지시가 충돌하면 **사용자 지시가 이긴다.**

## 3. 채택 보고

채택했으면 **한 줄로만** 보고한다. 역할 문서를 요약해 늘어놓지 않는다.

```
역할 채택: cpp-developer (.claude/agents/cpp-developer.md)
```

그 다음, 사용자가 이미 작업을 함께 지시했다면 바로 그 작업으로 넘어간다. 지시가
없었다면 무엇을 할지 묻지 말고 그냥 대기한다 — 채택 자체가 결과다.

## 4. 세션 동안 유지

- 채택한 역할은 **세션이 끝나거나 `/role` 이 다시 불릴 때까지** 유지한다.
- `/role` 이 다시 불리면 **이전 역할을 버리고 새 역할로 교체한다.** 겹쳐 쌓지 않는다.
- 컨텍스트가 요약(compaction)되어도 역할은 유지한다. 요약 시 **현재 역할 이름과 그
  역할의 핵심 규약을 반드시 요약에 남긴다.**
- 역할을 벗으려면 사용자가 `/role none` 이라고 한다. 이때는 채택을 해제하고
  기본 동작으로 돌아간 사실만 한 줄로 알린다.
